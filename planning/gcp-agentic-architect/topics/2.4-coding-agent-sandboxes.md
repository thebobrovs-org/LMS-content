# 2.4 Running coding agents safely in sandboxes

**Topic id:** `agentic-ai/coding-agent-sandboxes` · **Level:** 400 · **Difficulty:** advanced · **Est:** 25 min
**Track:** S2 Coding agents · **Exam objective:** 2.1 · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Agent-generated code is untrusted code. Running it on a developer laptop with production credentials is the scenario the exam wants you to reject.
- **What:** Where coding agents and their code run: Antigravity's terminal sandbox and permission presets, GKE Agent Sandbox for untrusted code, Cloud Workstations as a managed runtime; using agents to refactor, tune runtimes and patch vulnerabilities with human review.
- **How:** Map three scenarios (individual developer, enterprise team, agent-generated code executing at scale) to the right isolation, then walk a vulnerability-patch task with review gates.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `choose-sandbox`: Choose an isolation option for a scenario.
- `permission-presets`: Set permission presets that require approval for risky commands.
- `safe-refactor`: Run a refactor or security patch through an agent with tests and human review before merge.

## Must-learn (keep nothing else but this)
1. Treat agent-generated code as untrusted until reviewed and tested.
2. Isolate execution (sandbox, workstation, GKE Agent Sandbox) and keep production credentials out.
3. Human review stays in the loop for patches that ship.

## Key terms (glossary)
- `GKE Agent Sandbox`: Isolated execution of untrusted agent-generated code on GKE.
- `Cloud Workstations`: Managed cloud development environments, usable as coding-agent runtimes.
- `permission preset`: A coding agent setting that decides which actions run without approval.
