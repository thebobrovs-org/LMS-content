# 4.2 Building evaluation datasets for agents

**Topic id:** `agentic-ai/agent-eval-datasets` · **Level:** 200 · **Difficulty:** intermediate · **Est:** 25 min
**Track:** S4 Evaluate and deploy · **Exam objective:** 4.1 · **Persona:** `personas/agentic-ai.md`
**Status:** on staging

## Why / What / How
- **Why:** You cannot tell whether a prompt or model change helped without a fixed set of cases to compare on. Most agent regressions ship because no one had one.
- **What:** Golden datasets (inputs, expected tool calls, expected responses), edge and adversarial cases, ADK evalsets vs .test.json files, and user simulation for branching conversations.
- **How:** Build an evalset for the 3.2 support agent: happy paths, edge cases (missing data, ambiguous requests), an adversarial prompt, and a simulated user for a multi-turn case.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `golden-set`: Build a golden dataset with expected trajectories and responses.
- `edge-cases`: Add edge and adversarial cases that reflect production risk.
- `evalset-vs-test`: Choose an ADK evalset or a .test.json file, and when to use user simulation.

## Must-learn (keep nothing else but this)
1. An eval case records the expected tool trajectory as well as the expected answer.
2. Cover edge and adversarial cases, not just happy paths.
3. User simulation tests branching multi-turn conversations that fixed scripts cannot.

## Key terms (glossary)
- `golden dataset`: A curated set of inputs with expected outputs used as ground truth.
- `evalset`: An ADK file of eval cases, often multi-turn, for evaluating an agent.
- `user simulation`: A model playing the user to drive multi-turn evaluation.
