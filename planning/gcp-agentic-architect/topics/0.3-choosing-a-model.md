# 0.3 Choosing a model and how to serve it

## Why / What / How
- **Why:** Model choice fixes cost, latency, data residency and how much you can customise, and it is hard to change once tools and prompts are tuned to it.
- **What:** Three independent choices: LLM vs SLM, proprietary vs open model, and model-as-a-service vs self-deployed (Model Garden, Agent Platform endpoints, GKE).
- **How:** A decision table drives each axis from a requirement: latency and cost push to smaller models; data control or fine-tuning push to open weights you deploy; operational simplicity pushes to MaaS. Worked scenarios combine them.

## Must-learn (keep nothing else but this)
1. Size, openness and serving are separate decisions. Do not conflate 'open source' with 'self-hosted'.
2. Start with a managed model; move to self-deployed only for a stated need (data control, customisation, cost at scale).
3. A small model can handle routing and simple steps while a large model handles hard reasoning.

## Key terms (glossary)
- `SLM`: Small language model: fewer parameters, lower cost and latency, narrower ability.
- `MaaS`: Model as a service: a managed API endpoint with no infrastructure to run.
- `Model Garden`: Google Cloud's catalogue of first-party, partner and open models with deploy options.
- `self-deployed model`: A model you serve on your own endpoint or cluster (for example Gemma on GKE).
