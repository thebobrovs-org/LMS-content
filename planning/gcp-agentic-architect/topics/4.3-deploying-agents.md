# 4.3 Deploying agents: Agent Runtime, Cloud Run or GKE

## Why / What / How
- **Why:** The three runtimes are substitutes with different control, cost and operating burden. The exam gives a scenario and expects the cheapest option that meets its requirements.
- **What:** Agent Runtime (managed sessions, memory, scaling for agents), Cloud Run (serverless containers), GKE (full control, GPUs, custom networking); scaling settings; cost levers.
- **How:** A decision table, then three scenarios (a quick managed launch, an agent beside existing Cloud Run services, a regulated workload needing node control) with the reasoning shown.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `choose-runtime`: Choose Agent Runtime, Cloud Run or GKE from requirements.
- `scaling`: Set scaling (minimum and maximum instances, concurrency) for load and cost.
- `cost-levers`: Name the cost levers for a deployed agent.

## Must-learn (keep nothing else but this)
1. Agent Runtime, Cloud Run and GKE are substitutes; pick by control needed vs operations you will own.
2. Agent Runtime gives agent-specific managed services (sessions, memory); Cloud Run and GKE make you bring them.
3. Minimum instances trade cold starts for idle cost.

## Key terms (glossary)
- `Agent Runtime`: Managed runtime for agents with sessions, memory and scaling (formerly Agent Engine).
- `min instances`: Instances kept warm to avoid cold starts.
- `container concurrency`: Requests one instance handles at once.
