# 3.6 A2A and MCP: agents talking to agents and to tools

**Topic id:** `agentic-ai/a2a-and-mcp` · **Level:** 300 · **Difficulty:** advanced · **Est:** 25 min
**Track:** S3 Custom agents · **Exam objective:** 3.3 · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Confusing the two protocols is the commonest orchestration mistake: MCP connects an agent to tools; A2A connects independent agents, often owned by other teams.
- **What:** A2A (agent cards, discovery, tasks, messages) vs MCP (tools, resources); in ADK, a local sub-agent vs an AgentTool vs a remote A2A agent.
- **How:** One scenario, three designs: a sub-agent in the same process, an AgentTool, and a remote agent another team runs behind A2A. Compare coupling, ownership, identity and latency.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `a2a-vs-mcp`: Choose A2A or MCP for an integration.

- `local-vs-remote`: Choose a local sub-agent, AgentTool or remote A2A agent.

## Must-learn (keep nothing else but this)
1. MCP: agent-to-tool. A2A: agent-to-agent across process and team boundaries.
2. An agent card describes a remote agent's skills, endpoint and auth.
3. Go remote (A2A) when another team owns, scales or secures the agent.

## Key terms (glossary)
- `A2A`: Agent2Agent: an open protocol for agents to discover and call each other.
- `agent card`: A JSON document advertising an A2A agent's capabilities, endpoint and auth.
- `remote agent`: An agent running in another process or service, reached over A2A.
