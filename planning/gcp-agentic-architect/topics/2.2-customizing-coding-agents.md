# 2.2 Customizing coding agents: rules, hooks, skills, subagents and plugins

## Why / What / How
- **Why:** Teams want agents to follow house conventions and enforce checks. Each customisation mechanism has a different guarantee, and picking the wrong one leaves a rule unenforced.
- **What:** Rules (always-on guidance), hooks (deterministic actions on events), skills (on-demand know-how), custom subagents (delegated roles with their own context) and plugins (packaging to share them), plus Skill Registry for org-wide sharing.
- **How:** A decision table, then one requirement solved five ways to show which mechanism actually guarantees the outcome (a hook runs every time; a rule only asks).

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `pick-mechanism`: Choose a rule, hook, skill, subagent or plugin for a requirement.
- `enforce-vs-guide`: Explain why a hook enforces and a rule only guides.
- `share-customizations`: Package customisations as a plugin and share skills through Skill Registry.

## Must-learn (keep nothing else but this)
1. If it must happen every time, use a hook. If it is guidance, use a rule or skill.
2. Subagents isolate context for a focused role.
3. Plugins package customisations for distribution; Skill Registry shares skills across an organisation.

## Key terms (glossary)
- `rule`: Persistent guidance always present in the agent's context.
- `hook`: A script the agent harness runs on a lifecycle event.
- `subagent`: A delegated agent with its own instructions and context.
- `plugin`: A package that bundles skills, hooks, rules and settings.
- `Skill Registry`: A managed catalogue for sharing skills across an organisation (Preview).
