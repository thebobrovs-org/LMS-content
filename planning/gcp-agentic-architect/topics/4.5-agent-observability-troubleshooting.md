# 4.5 Observing and troubleshooting agents in production

**Topic id:** `agentic-ai/agent-observability-troubleshooting` · **Level:** 400 · **Difficulty:** advanced · **Est:** 30 min
**Track:** S4 Evaluate and deploy · **Exam objective:** 4.2 · **Persona:** `personas/agentic-ai.md`
**Status:** plan-approved

## Why / What / How
- **Why:** Agents fail in new ways: they loop, call slow tools, drift as data and models change, and hallucinate. Traces are how you find which.
- **What:** The observability stack (Cloud Trace spans for model and tool calls, Cloud Logging, metrics, dashboards) and a symptom → signal → fix table for latency, reasoning loops, drift, failures, hallucination and cost.
- **How:** An annotated trace of a slow, looping request: the learner finds the repeated tool call and the slow downstream API, then applies the fix from the table.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `read-trace`: Read an agent trace to find slow spans and repeated calls.
- `diagnose`: Map a symptom to its likely cause and the signal that confirms it.
- `optimize`: Choose a fix for latency, loops, drift or cost.

## Must-learn (keep nothing else but this)
1. Trace every model and tool call; you cannot fix a loop you cannot see.
2. Reasoning loops are fixed with better tool descriptions, stop conditions and caps.
3. Drift is caught by continuous evaluation (4.2), not by uptime checks.

## Key terms (glossary)
- `span`: One timed operation in a trace, such as a model or tool call.
- `drift`: Quality degrading over time as inputs, data or models change.
- `reasoning loop`: An agent repeating steps without progress.
