## Why / What / How
- **Why:** ADK is the exam's centre of gravity and the base of the hands-on labs. Testers advise knowing it broadly and building one small agent end to end.
- **What:** ADK's LlmAgent (model, instruction, tools), function tools and built-in tools, sub-agents, AgentTool, and callbacks (before/after model and tool) for checks and edits.
- **How:** Build a small support agent step by step: one function tool, then a sub-agent, then a before-tool callback that blocks a disallowed argument. Each step is a `<Step>` with a code block.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `build-llmagent`: Define an LlmAgent with a model, instruction and function tools.
- `compose-agents`: Add sub-agents or wrap an agent as an AgentTool and say how control differs.
- `use-callbacks`: Use a callback to validate or modify a model or tool call.

## Must-learn (keep nothing else but this)
1. A tool's docstring and type hints are what the model sees; write them for the model.
2. Sub-agents receive control (transfer); an AgentTool is called and returns a result, like a function.
3. Callbacks are where deterministic checks live inside an agent.

## Key terms (glossary)
- `ADK`: Agent Development Kit: Google's open-source framework for building agents in code.
- `LlmAgent`: ADK's model-driven agent with instructions and tools.
- `AgentTool`: An ADK wrapper that lets one agent call another as a tool.
- `callback`: A hook ADK runs before or after a model or tool call.
