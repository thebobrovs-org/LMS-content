# 1.2 CX Agent Studio: flows, routes and instructions

**Topic id:** `agentic-ai/cx-agent-studio-flows` · **Level:** 200 · **Difficulty:** intermediate · **Est:** 30 min
**Track:** S1 Low-code agents · **Exam objective:** 1.1 · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Customer-facing agents need predictable paths for payments, authentication and handoffs. Route scope is the most-missed detail: a route on one page does not fire while another page is active.
- **What:** Instruction-based vs flow-based agents in CX Agent Studio; the state machine of flows, pages, transition routes (intent or condition) and event handlers; route scope; instructions with XML structure, few-shot examples and references.
- **How:** A sim of a small flow lets the learner set the current page and session parameters and see which route or handler wins. Then the lesson writes the instruction block for the instruction-based half, with few-shot examples.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `instruction-vs-flow`: Choose an instruction-based or flow-based agent for a use case.
- `predict-route`: Predict which route or event handler fires from the active page and parameters.
- `write-instructions`: Write agent instructions with structure, few-shot examples and chain-of-thought guidance.

## Must-learn (keep nothing else but this)
1. Routes are evaluated in scope: the current page's routes, then the flow's start-page routes, in order.
2. Event handlers catch no-match, no-input and similar events; without one the agent falls back to defaults.
3. Use flows where a path must be deterministic; use instructions where conversation can be open.

## Key terms (glossary)
- `flow`: A group of pages that models one conversation topic.
- `page`: A state in a flow with its own routes, parameters and handlers.
- `transition route`: A rule (intent and/or condition) that moves the conversation to another page.
- `event handler`: A rule that responds to an event such as no-match or no-input.
- `few-shot example`: An example exchange included in instructions to steer behaviour.
