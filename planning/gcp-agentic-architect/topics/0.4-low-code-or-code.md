# 0.4 Low-code or code: designing hybrid agents

**Topic id:** `agentic-ai/low-code-or-code` · **Level:** 300 · **Difficulty:** advanced · **Est:** 25 min
**Track:** Core · **Exam objective:** 1.1, 1.2, 3.1 · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Real systems mix both: a Gemini Enterprise or CX Agent Studio front end that calls ADK agents and tools behind it. Scenario questions ask when to stay low-code and when to move to code.
- **What:** Criteria for choosing low-code (Workflow Builder, CX Agent Studio) vs ADK; hybrid designs (low-code agents calling tools, MCP servers or ADK agents; ADK agents surfaced in Gemini Enterprise); the cost of migrating later.
- **How:** Three scenarios with a design for each, and a table of the limits that push a design from low-code to code (custom logic, evaluation depth, deployment control, multi-agent coordination).

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `choose-build-approach`: Choose low-code, code or a hybrid for a scenario and defend it.
- `hybrid-design`: Design a low-code front end that calls code-built agents or tools.
- `migration-signals`: Name the signals that a low-code agent should move to code.

## Must-learn (keep nothing else but this)
1. Start low-code when the platform covers the need; move to code for control it cannot give.
2. Hybrids are normal: low-code for the experience, code for the hard logic.
3. Decide early where evaluation and identity will live, since that is what migrations break.

## Key terms (glossary)
- `hybrid agent`: A system combining low-code agents with code-built agents or tools.
