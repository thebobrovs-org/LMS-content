# 3.7 Orchestrating multiple agents

**Topic id:** `agentic-ai/multi-agent-orchestration` · **Level:** 400 · **Difficulty:** advanced · **Est:** 30 min
**Track:** S3 Custom agents · **Exam objective:** 3.3 · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Splitting work across agents helps only with the right pattern. Parallel branches writing the same state key, or an LLM router where a fixed sequence would do, are classic failures.
- **What:** Sequential, parallel and loop patterns, graph-based workflows, and LLM-driven handoffs; shared state between branches; when deterministic orchestration beats an LLM router.
- **How:** A sim runs the same task as sequential, parallel and loop orchestration, showing time, ordering and a shared-state collision when two parallel branches write one key.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `pick-pattern`: Choose sequential, parallel, loop, graph or LLM-routed orchestration for a task.
- `shared-state`: Avoid parallel branches overwriting shared state.
- `loop-exit`: Design a loop with an exit condition and an iteration cap.

## Must-learn (keep nothing else but this)
1. Use deterministic orchestration when the order is known; LLM routing only when it is not.
2. Parallel branches must write distinct state keys.
3. Every loop needs an exit condition and a cap.

## Key terms (glossary)
- `sequential agent`: Runs sub-agents in a fixed order.
- `parallel agent`: Runs sub-agents concurrently and gathers their results.
- `loop agent`: Repeats sub-agents until a condition or cap.
- `graph workflow`: Orchestration defined as nodes and edges, with branching.
