# 5.3 Authenticating agent tool calls with OAuth 2.0

**Topic id:** `agentic-ai/agent-auth-oauth` · **Level:** 300 · **Difficulty:** advanced · **Est:** 35 min
**Track:** S5 Secure and govern · **Exam objective:** 5.1 · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Testers rate OAuth harder than its weight, and it appears in the labs. The key decision is whose authority a tool call uses: the agent's or the user's.
- **What:** OAuth 2.0 vs OpenID Connect; 2-legged (agent acts as itself) vs 3-legged (agent acts for a user with consent); Agent Identity's auth manager; ADK AuthScheme, AuthCredential and AuthConfig and the pause-and-resume consent flow.
- **How:** Two sequence diagrams (2LO and 3LO), then the ADK flow as `<Steps>`: the tool requests credentials, the agent pauses, the user consents, the agent resumes with a token.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `oauth-vs-oidc`: Distinguish OAuth 2.0 (authorisation) from OpenID Connect (authentication).
- `2lo-vs-3lo`: Choose 2-legged or 3-legged OAuth for a tool call.
- `adk-auth`: Configure ADK tool authentication and handle the consent pause and resume.

## Must-learn (keep nothing else but this)
1. OAuth authorises access; OIDC proves who the user is.
2. 3LO when the agent acts on a user's data with their consent; 2LO when it acts as itself.
3. In ADK the agent pauses for consent and resumes with the credential; it never sees the user's password.

## Key terms (glossary)
- `OAuth 2.0`: An authorisation framework for delegated access with tokens.
- `OpenID Connect`: An identity layer on OAuth 2.0 that issues ID tokens.
- `2LO / 3LO`: Two-legged (client credentials) and three-legged (user consent) OAuth flows.
- `AuthConfig`: ADK object describing how a tool authenticates.
