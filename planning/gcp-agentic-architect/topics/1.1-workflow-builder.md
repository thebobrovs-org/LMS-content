# 1.1 Workflow Builder: chat agents and workflows

**Topic id:** `agentic-ai/workflow-builder` · **Level:** 100 · **Difficulty:** beginner · **Est:** 25 min
**Track:** S1 Low-code agents · **Exam objective:** 1.1 · **Persona:** `personas/agentic-ai.md`
**Status:** plan-approved

## Why / What / How
- **Why:** Many business automations need no code. Choosing a chat agent when the job is a repeatable approval flow, or the reverse, is a common scenario mistake.
- **What:** Workflow Builder in Gemini Enterprise: chat agents vs workflows, triggers (manual, schedule, event), steps (Gemini Agent, Condition, Request info, loops), human review, versions and run logs.
- **How:** Build the same onboarding request twice: as a chat agent (open-ended) and as a workflow (event trigger, Gemini Agent step with structured output, a condition, a human approval). Compare what each guarantees.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `chat-vs-workflow`: Choose a chat agent or a workflow for a use case.
- `configure-workflow`: Configure a trigger, a Gemini Agent step with instructions, knowledge and connectors, a condition and a human review step.
- `operate-workflow`: Use versions and step-by-step run logs to change and debug a workflow.

## Must-learn (keep nothing else but this)
1. Chat agents are conversational and open-ended; workflows are sequenced steps with conditions and human approvals.
2. An event trigger is configured from a connector data change, not drawn as a canvas node.
3. Put the human approval before any irreversible step.

## Key terms (glossary)
- `Workflow Builder`: The low-code builder in Gemini Enterprise for chat agents and workflows (formerly Agent Designer).
- `trigger`: What starts a workflow: manual, schedule or event.
- `Gemini Agent step`: A workflow step where a model acts on instructions, knowledge and connectors.
