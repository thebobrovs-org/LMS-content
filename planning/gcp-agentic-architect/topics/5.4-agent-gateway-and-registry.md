# 5.4 Agent Gateway and Agent Registry

**Topic id:** `agentic-ai/agent-gateway-and-registry` · **Level:** 300 · **Difficulty:** advanced · **Est:** 25 min
**Track:** S5 Secure and govern · **Exam objective:** 5.1, 5.2 · **Persona:** `personas/agentic-ai.md`
**Status:** on staging

## Why / What / How
- **Why:** Once many agents call many tools, you need one place to see and control the traffic and one catalogue of what is allowed to exist.
- **What:** Agent Gateway (a policy and monitoring point for agent traffic: access policies, monitoring, guardrail hooks) and Agent Registry (identifiers for agents, MCP servers and endpoints; governance role).
- **How:** Route the path's example agents through a gateway with an access policy and show what is logged; register them and their tools so the policy can name them.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):

## Must-learn (keep nothing else but this)
1. Gateway = runtime control and visibility of agent traffic.
2. Registry = the catalogue that policies and discovery refer to.
3. Identity (5.2) answers who; the gateway answers what they may do now; the registry answers what exists.

## Key terms (glossary)
- `Agent Gateway`: A managed gateway that applies access policies to and monitors agent traffic.
- `Agent Registry`: A catalogue of agents, MCP servers and endpoints with stable identifiers.
