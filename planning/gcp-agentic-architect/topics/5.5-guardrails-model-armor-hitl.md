# 5.5 Guardrails: Model Armor, data protection and human in the loop

**Topic id:** `agentic-ai/guardrails-model-armor-hitl` · **Level:** 400 · **Difficulty:** advanced · **Est:** 30 min

## Why / What / How
- **Why:** Prompt injection, data leakage and irreversible actions are the risks that make agents dangerous. Layered guardrails are the answer the exam expects.
- **What:** Model Armor (prompt and response screening, templates, floor settings, enforcement modes), Sensitive Data Protection inside Model Armor (basic vs advanced), human-in-the-loop with ADK tool confirmation, and propagating user identity so an agent never reads more than the user could.
- **How:** Defend the support agent in layers: Model Armor on input and output, SDP for card numbers, a confirmation step before refunds, and user identity carried to the data source. A table maps each threat to its layer.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `model-armor`: Configure Model Armor templates, floor settings and enforcement.
- `sdp`: Choose basic or advanced Sensitive Data Protection.
- `hitl`: Require human confirmation for irreversible tool calls with ADK.
- `identity-propagation`: Propagate user identity so retrieval respects the user's permissions.

## Must-learn (keep nothing else but this)
1. Guardrails are layers: screen input and output, protect sensitive data, confirm risky actions, limit identity.
2. Human confirmation belongs on irreversible or high-impact actions.
3. An agent should act with the user's permissions, not wider ones, when it acts for a user.

## Key terms (glossary)
- `Model Armor`: Google Cloud service that screens prompts and responses for injection, harmful content and sensitive data.
- `floor setting`: An organisation-wide minimum Model Armor configuration.
- `Sensitive Data Protection`: Google Cloud service that detects and de-identifies sensitive data.
- `human in the loop`: A required human approval before an agent action proceeds.
