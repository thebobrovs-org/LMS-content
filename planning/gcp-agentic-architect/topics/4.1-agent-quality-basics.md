# 4.1 What good looks like: agent quality basics

**Topic id:** `agentic-ai/agent-quality-basics` · **Level:** 100 · **Difficulty:** beginner · **Est:** 15 min
**Track:** S4 Evaluate and deploy · **Exam objective:** 4.1, 4.2 (introduction) · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Teams ship agents on a few happy demos. Knowing what to measure, and that an agent can give the right answer the wrong way, is the starting point for every eval and ops topic.
- **What:** The dimensions of agent quality: final response, the path taken (trajectory), retrieval quality, safety, latency and cost; offline evaluation before launch vs online monitoring after.
- **How:** Score one agent run on each dimension and show a run that gets the right answer through a wrong or unsafe tool path.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `quality-dimensions`: Name the dimensions of agent quality and an example failure for each.
- `right-answer-wrong-way`: Explain why checking only the final answer misses agent failures.
- `offline-vs-online`: Distinguish offline evaluation before launch from online monitoring after it.

## Must-learn (keep nothing else but this)
1. Judge the path (trajectory) as well as the answer.
2. Evaluate before launch and keep monitoring after; agents drift.

## Key terms (glossary)
- `trajectory`: The sequence of tool calls an agent made.
- `offline evaluation`: Testing on a fixed dataset before release.
- `online monitoring`: Measuring quality on live traffic.
