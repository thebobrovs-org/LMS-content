# 3.3 Sessions, state and Memory Bank

**Topic id:** `agentic-ai/sessions-state-memory` · **Level:** 200 · **Difficulty:** intermediate · **Est:** 25 min
**Track:** S3 Custom agents · **Exam objective:** 3.1 · **Persona:** `personas/agentic-ai.md`
**Status:** planned

## Why / What / How
- **Why:** Agents that forget the conversation feel broken; agents that remember everything leak data and cost tokens. The exam asks where each kind of data belongs.
- **What:** ADK sessions and events, session state and its scopes, managed sessions in Agent Platform, and Agent Platform Memory Bank for long-term memory across sessions.
- **How:** Follow one user across two sessions: what lives in the event history, what in session state, and what Memory Bank extracts and recalls later.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `session-vs-memory`: Distinguish a session's history and state from long-term memory.
- `state-scopes`: Choose the right state scope for a value.
- `memory-bank`: Configure Memory Bank to keep and recall facts across sessions.

## Must-learn (keep nothing else but this)
1. Session = one conversation's events and state. Memory = facts kept across conversations.
2. Keep only what you need; long-term memory is personal data with retention rules.
3. Managed sessions remove the need to run your own session store in production.

## Key terms (glossary)
- `session`: One conversation thread: its events and state.
- `session state`: Key-value data an agent reads and writes during a session.
- `Memory Bank`: Agent Platform's managed long-term memory that extracts and retrieves facts across sessions.
