# 4.4 Evaluation criteria and continuous evaluation

**Topic id:** `agentic-ai/agent-eval-criteria` · **Level:** 300 · **Difficulty:** advanced · **Est:** 35 min
**Track:** S4 Evaluate and deploy · **Exam objective:** 4.1 · **Persona:** `personas/agentic-ai.md`
**Status:** plan-approved

## Why / What / How
- **Why:** Picking the wrong metric hides the failure you care about. Testers report a trap: an LLM judge cannot tell you which tools ran, in what order, under whose identity.
- **What:** ADK criteria (tool trajectory match: exact, in-order, any-order; response match; LLM-judged; rubric-based), choosing ADK eval vs the Gen AI evaluation service vs custom autoraters, and continuous evaluation in CI and production.
- **How:** A sim compares an expected trajectory with actual ones under each match mode; the learner sees which modes pass a harmless reordering and which catch a missing or extra call. Then the lesson builds a CI gate plus a production monitor.

## Learning objectives
After this topic the learner can (ids become the lesson's `objectives`):
- `trajectory-modes`: Predict whether a trajectory passes exact, in-order or any-order matching.
- `pick-criterion`: Choose a deterministic or model-judged criterion for what must be checked.
- `pick-tooling`: Choose ADK eval, the Gen AI evaluation service or a custom autorater.
- `continuous-eval`: Design continuous evaluation across CI and production.

## Must-learn (keep nothing else but this)
1. Check tool calls and order with trajectory matching, not an LLM judge.
2. Use model-judged and rubric criteria for qualities without one right answer.
3. Evaluate in CI before release and monitor online after it.

## Key terms (glossary)
- `trajectory`: The sequence of tool calls an agent made.
- `tool trajectory match`: Comparing actual tool calls to expected ones (exact, in-order or any-order).
- `autorater`: A model used to score outputs against criteria.
- `Gen AI evaluation service`: Agent Platform's managed evaluation for models and agents.
