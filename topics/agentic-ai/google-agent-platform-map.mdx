## Why a map first

Google renamed most of its agent products in 2025 and 2026. Docs, blog posts,
console screens and old practice questions now use different names for the same
thing, and a scenario question is only answerable if you know what each product
is for. This lesson gives you one map. Every later lesson in the path zooms into
one of its boxes.

Most of the map lives in Gemini Enterprise
<Term id="Agent Platform">Agent Platform</Term> (Agent Platform for short),
which Google describes as the evolution of Vertex AI for building, scaling,
governing and optimising agents. Despite the shared name,
<Term id="Gemini Enterprise">Gemini Enterprise</Term> is a separate product: the
app where employees find and use agents.

## The map

Read the map top to bottom, from the people who use agents down to where agents
run. Governance is not a layer of its own: it wraps all of them.

- **Experience (low-code).** **Gemini Enterprise** is where employees discover,
  create, run and govern agents. Its **Workflow Builder** builds agent workflows
  visually, without code. **CX Agent Studio** builds customer-facing
  conversational agents, for example for a contact centre. Google calls it the
  evolution of Dialogflow CX.
- **Build (code).** The **Agent Development Kit (ADK)** is Google's open-source,
  code-first framework for agents. **Agents CLI** gives a coding agent Google's
  packaged instructions and scripts for building with ADK, evaluating, deploying,
  observing and publishing. **Antigravity** is Google's agent-first development environment
  (app, CLI and SDK) for steering coding agents.
- **Models.** **Gemini models** do the reasoning, and **Model Garden** offers
  Google, partner and open models.
- **Knowledge.** **Agent Search** is managed search and retrieval over your
  documents. **RAG Engine** is a framework for building your own
  retrieval-augmented pipeline. **Agent Retrieval** and the original **Vector
  Search** store and search embeddings, the lists of numbers that capture what a
  passage means, so that similar passages can be found. **MCP (Model Context
  Protocol) servers** expose Google Cloud services and your own systems as tools.
  Underneath sit the data stores an agent reads: **BigQuery**, **Cloud SQL**,
  **Firestore**, **Memorystore for Redis** and **Cloud Storage**.
- **Run.** <Term id="Agent Runtime">Agent Runtime</Term> is the managed runtime
  that deploys, operates and scales agents, with Agent Platform's Sessions and
  Memory Bank services keeping their state. **Cloud Run** runs an agent as a serverless container, and
  **GKE** gives full control of a Kubernetes cluster.
- **Evaluate.** The **Gen AI evaluation service** scores answers and tool-call
  paths (trajectories) against a test set. **Cloud Logging** and **Cloud Trace** show what an
  agent did in production.
- **Govern.** **Agent Identity** gives each agent its own identity. **Agent
  Gateway** is the point where policy on agent traffic is enforced and observed.
  **Agent Registry** catalogues agents, MCP servers and tools, and **Skill
  Registry** is being folded into it. **Model Armor** screens prompts and responses for attacks such as
  prompt injection and for leaks of sensitive data. **Sensitive Data
  Protection** finds and masks sensitive data.

<Callout type="note">Agents talk to tools over MCP (Model Context Protocol) and to other agents over A2A (Agent2Agent). These are protocols, not products, so they connect the boxes rather than sitting in one. A later lesson compares them.</Callout>

The shape is the thing to remember. Low-code tools sit on top, for people who
configure agents rather than code them. ADK, the models and the runtime sit
underneath, for developers. Identity, the gateway and the registry wrap
everything, because an agent needs governing however it was built.

## Translating the old names

When a source uses an old name, translate it before you reason about it:

| Former name | Current name | When | Source |
|---|---|---|---|
| Vertex AI (for agents) | Gemini Enterprise Agent Platform | April 2026 | Google Cloud blog |
| Vertex AI Agent Engine | Agent Runtime | by April 2026 | Google Cloud blog |
| Vertex AI Search | Agent Search | April 2026 | release notes |
| Agent Designer | Workflow Builder | September 2026 (GA) | release notes |
| Vector Search 2.0 | Agent Retrieval | by May 2026 | product docs |

Renames don't reach every surface at once. When Google renamed Vertex AI Search,
the console still showed the old name, and the APIs kept their Discovery Engine
endpoints. So expect old names in code, URLs and screenshots, and trust the
product's current documentation and the exam guide over an older blog post.
